## Design Specificity Verdict

### LLM assessment

The result feels authored for Nudge, not interchangeable with a generic fitness app. Signal-yellow action planes, hard black rules, condensed headings, numbered exercise rows, and the persistent Plan → Perform → Cooldown → Review marker create a coherent “clear signal” operating interface for a trainee using a phone around equipment.

Specificity weakens where the implementation contradicts that idea. The active-rest state presents Start Set and Finish Workout as equally large yellow actions, while the Plan state makes the user pass a seven-item optional constraint group before reaching the product-defining action. The visual language is specific; the decision hierarchy is not yet consistently enforcing it.

## Overall Impression

Nudge now has a confident, recognizable interface that protects the next set better than the previous direction. The biggest opportunity is to make the product’s “one next useful decision” principle govern every state—not only the focused set. Plan currently delays its defining action, active rest offers two dominant exits, and completion ends without a clear factual save moment.

## What’s Working

1. **A distinctive visual operating language.** Signal yellow, ink planes, hard rules, condensed display type, and oversized actions are legible around equipment and feel specific to Nudge.
2. **The Perform hierarchy is mostly excellent.** The focused set comes first, alternate exercises remain reachable, and deferred set details stay available without competing with the active decision.
3. **Accessibility fundamentals are built in.** Labelled controls, `aria-current`, live status regions, explicit focus movement, strong contrast, large touch targets, and reduced-motion handling support the intended phone-first use.

## Cognitive Load

The journey has moderate cognitive load with three notable failures:

- The seven muscle-group exclusions are one undifferentiated optional choice group.
- The Plan action is below that group rather than immediately following the time decision.
- Active rest can show two equally dominant yellow actions.

The focused set, alternate exercises, and deferred-set disclosure otherwise manage working memory well. The five visible exercise choices in workout-ready are intentional agency, not unnecessary planning burden.

## Emotional Journey

- **Plan:** Calm and relevant because it begins with available time, but the optional exclusions slow the product’s strongest promise.
- **Workout ready:** The clearest positive peak; the large action and immediate exercise preview create momentum without praise or pressure.
- **Active work/rest:** Factual timing reassures, but a prominent Finish Workout action introduces an unintended “are you done?” prompt while the user should be preparing for the next set.
- **Review/completion:** Functionally sound but emotionally flat. Returning directly to Plan after save does not provide a clear factual end beat such as “Workout saved.”

## Priority Issues

### [P1] The Plan action sits below the optional decision burden

- **Why it matters:** The product-defining action is absent from the initial 390×844 and 1280×900 Plan evidence. Busy or interrupted trainees must traverse seven optional exclusions before they can ask Nudge to plan.
- **Fix:** Place Plan my workout directly after the time control or keep it persistently reachable near the bottom edge. Move “Anything to work around?” into a compact optional disclosure or a visibly secondary region.
- **Suggested command:** `$impeccable layout`

### [P1] Active rest presents two dominant yellow actions

- **Why it matters:** Start Set and Finish Workout share scale, color, and arrow treatment in the same mobile view. That breaks the approved one-signal hierarchy and introduces exit pressure during focused work.
- **Fix:** Keep Start Set as the sole yellow action while a set is ready. Render Finish Workout as a compact outlined or text action, separated from the focused set and alternatives.
- **Suggested command:** `$impeccable distill`

### [P1] Successful completion lacks a visible factual end state

- **Why it matters:** The user returns to Plan immediately after save, so the journey ends with navigation rather than certainty that the workout was stored.
- **Fix:** Retain a brief, accessible “Workout saved” completion state or carry a persistent success status onto Plan. Show concise duration/set facts without praise, celebration, or gamification.
- **Suggested command:** `$impeccable harden`

### [P2] Several labels expose internal or expert vocabulary

- **Why it matters:** “Met the floor,” “items confirmed,” and exact-save/recovery phrases require interpretation at moments when the trainee is moving, interrupted, or diagnosing a problem.
- **Fix:** Prefer “sets confirmed” and factual recommendation provenance in ordinary training language. Keep recovery explanations specific but remove implementation vocabulary where it is not necessary for safe action.
- **Suggested command:** `$impeccable clarify`

### [P2] Recovery discard is too easy for an interruption-sensitive flow

- **Why it matters:** A mistaken tap can destroy the state recovery exists to protect. This is most hazardous for one-handed, interrupted trainees.
- **Fix:** Outside TREK-233’s no-recovery-semantics boundary, label the action “Discard saved workout” and require confirmation when confirmed work exists. Keep Resume visually primary.
- **Suggested command:** `$impeccable harden`

## Persona Red Flags

### Casey — distracted mobile trainee

- Plan my workout is below a seven-choice vertical list.
- Start Set and Finish Workout compete during active rest, increasing attention switching and mis-tap risk.
- Returning to a scrolled ready set can reveal a disabled action while its Start Workout explanation is offscreen.
- Recovery preserves state, but direct Discard is hazardous for one-handed use.

### Sam — accessibility-dependent trainee

- Semantic controls, visible focus, live regions, current-step text, reduced motion, and labelled numeric inputs are strong.
- Dense exercise status strings and recovery/save terminology increase screen-reader parsing load.
- A disabled Start Set can lose local explanatory context after scrolling.
- Native confirmation patterns elsewhere in the journey can interrupt the otherwise authored focus sequence.

### Morgan — irregular-schedule solo trainee

- Time-first planning directly respects an irregular schedule and avoids guilt or streak pressure.
- Seven exclusions make a quick “I have 25 minutes” decision feel like setup work.
- A prominent finish action during active rest distracts from the one useful next set.
- Completion does not clearly confirm that the session was saved before returning to planning.

## Minor Observations

- Manage Catalog is prominent in the shared header and uses insider terminology; a quieter affordance or “Exercises” would be easier for beginners.
- The oversized Plan headline contributes to the primary action falling below both captured first viewports.
- Workout history remains available during active performance, adding a low-value distraction to the core training state.
- Review could disclose detailed timing after showing only the facts needed to verify and save the session.
- The recovery screenshot in the fallback set reflects stale browser evidence, not the intended Perform state; it was not treated as product truth.

## Questions to Consider

- If exclusions are optional, why must every trainee pass them before reaching Nudge’s defining action?
- Should Finish Workout ever receive signal yellow while a ready set exists?
- Can the journey end with certainty—“Workout saved”—without praise, gamification, or coaching?
- Which recommendation facts help agency, and which implementation terms merely expose the engine?
